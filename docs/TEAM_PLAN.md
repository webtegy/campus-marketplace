# Group 16 — Team Plan

These are planned integration areas, not claims of completed features or
individual authorship. The starter already contains basic UI, authentication,
and publishing code. Each contribution must distinguish inherited behavior from
new work. Setup work does not include implementing the other four areas.

## Integration order

| Stage | Area | Main responsibilities |
|---|---|---|
| 1 | Setup | Environment template, development checks, documentation |
| 2 | Accounts and data | Authentication, Firebase services, application state |
| 3 | Browsing and favorites | Explore, search, categories, saved listings |
| 4 | Seller tools | Create, edit, delete, validation, sold status |
| 5 | Messaging and integration | Conversations, messages, final interface checks |

## Working agreement

Each member must understand their assigned area and make a meaningful
contribution through implementation, fixes, testing, or documentation.

Existing code retains accurate authorship. Integration stages do not
establish authorship of previously completed work.

## Pull request checklist

- Explain the problem and resulting behavior.
- Identify the files changed.
- Run TypeScript and lint checks.
- Test the affected user flow.
- Record any remaining limitations.
- Request review from another group member.

## Demo responsibilities

Each member explains their actual contribution and demonstrates the
relevant behavior or development process.

## Final documentation

Before submission, update the README with:

- Actual member names.
- Completed features.
- Accurate individual contributions.
- Verified setup instructions.
- Known limitations.
